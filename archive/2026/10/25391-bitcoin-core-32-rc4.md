<!-- wp:paragraph -->
<p>Bitcoin Core 32.0 moved to a fourth release candidate on October 14, 2026, keeping the next major node release in public testing rather than jumping straight to a final build.</p>
<!-- /wp:paragraph -->

<!-- wp:paragraph -->
<p>Maintainer fanquake announced <a href="https://delvingbitcoin.org/t/bitcoin-core-32-0rc4-is-now-available/2958">v32.0rc4 on Delving Bitcoin</a>, with signed binaries available from Bitcoin Core and source under the signed Git tag. The project describes RC4 as a test build: if no critical problems are found, a candidate can become the final v32.0 release.</p>
<!-- /wp:paragraph -->

<!-- wp:paragraph -->
<p>RC4 follows the <a href="https://bitcoinversus.tech/2026/10/10/bitcoin-core-32-third-release-candidate/">RC3 build we covered on October 10</a>. Bitcoin Core’s <a href="https://github.com/bitcoin/bitcoin/issues/36315">32.0 testing issue</a> is still asking contributors to test supported operating systems and integrations and report reproducible problems.</p>
<!-- /wp:paragraph -->

<!-- wp:paragraph -->
<p>The broader 32.0 cycle includes new RPCs, PSBT v2 defaults, a combined fee estimator, wallet tooling and an HTTP-server rewrite. For context, see our explainers on <a href="https://bitcoinversus.tech/2026/10/08/bitcoin-it-what-is-bitcoin-core-rpc-bitcoin-cli-json-rpc/">Bitcoin Core RPC</a> and why <a href="https://bitcoinversus.tech/2026/10/14/bitcoin-nodes-enforce-the-rules/">Bitcoin nodes enforce the rules</a>.</p>
<!-- /wp:paragraph -->

<!-- wp:paragraph -->
<p>The important distinction is that RC4 is <strong>not a new Bitcoin consensus rule</strong>. It is software being tested before a stable release, so production operators should treat it as a release candidate rather than automatically upgrading critical nodes.</p>
