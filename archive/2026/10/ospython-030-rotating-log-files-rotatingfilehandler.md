<!-- wp:paragraph --><p><strong>Python log files can grow forever unless an application limits them. <code>RotatingFileHandler</code> solves one specific problem: when a log reaches a chosen size, Python can rename it as a backup and continue writing to a fresh file.</strong></p><!-- /wp:paragraph -->

<!-- wp:heading --><h2 class="wp-block-heading">Rotate A Log By File Size</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p><code>RotatingFileHandler</code> lives in <code>logging.handlers</code>. Two settings control the basic rotation behavior: <code>maxBytes</code> sets the approximate file size that triggers a rollover, and <code>backupCount</code> sets how many older files Python keeps.</p><!-- /wp:paragraph -->
<!-- wp:paragraph --><p><code>import logging</code><br><code>from logging.handlers import RotatingFileHandler</code><br><code>logger = logging.getLogger(__name__)</code><br><code>logger.setLevel(logging.INFO)</code><br><code>handler = RotatingFileHandler("app.log", maxBytes=1_000_000, backupCount=3)</code><br><code>logger.addHandler(handler)</code><br><code>logger.info("Application started")</code></p><!-- /wp:paragraph -->
<!-- wp:paragraph --><p>In this example, <code>app.log</code> rolls over after it grows to roughly one megabyte. Python can then keep backup files such as <code>app.log.1</code>, <code>app.log.2</code>, and <code>app.log.3</code> while the active application continues writing to a new <code>app.log</code>.</p><!-- /wp:paragraph -->

<!-- wp:heading --><h2 class="wp-block-heading">Understand maxBytes And backupCount</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p><code>maxBytes</code> answers, “How large may the active log become before rollover?” <code>backupCount</code> answers, “How many old rotated files should remain?” Together they stop a single application log from consuming storage without limit.</p><!-- /wp:paragraph -->
<!-- wp:paragraph --><p>If <code>backupCount=0</code>, normal rollover backups are not retained. If the backup count is small, older generations disappear sooner as newer rotations occur. Choose limits based on how much diagnostic history you need and how much disk space the system can safely use.</p><!-- /wp:paragraph -->

<!-- wp:heading --><h2 class="wp-block-heading">Basic Troubleshooting</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p>If rotation never happens, check whether the active file has actually reached <code>maxBytes</code>. Also confirm that the process has permission to create and rename files in the log directory.</p><!-- /wp:paragraph -->
<!-- wp:paragraph --><p>If expected messages are missing, check both the logger level and handler level. Rotation controls file size and retention; it does not override severity filtering. Keep passwords, API keys, authentication tokens, and other secrets out of routine logs.</p><!-- /wp:paragraph -->
