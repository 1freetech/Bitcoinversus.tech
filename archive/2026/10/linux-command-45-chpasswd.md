<!-- wp:heading --><h2 class="wp-block-heading">Elementary Overview</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p>On <strong>Linux</strong>, <strong><code>chpasswd</code></strong> changes passwords for multiple existing user accounts from standard input. It is the batch-oriented counterpart to <a href="https://bitcoinversus.tech/2026/10/02/linux-command-37-passwd/"><strong><code>passwd</code></strong></a>: instead of opening an interactive password prompt for one account at a time, <code>chpasswd</code> reads lines in the form <code>username:password</code> and applies the changes in one administrative workflow. That makes it useful in controlled provisioning, lab automation, and other environments where several local accounts must be updated together. The upstream <a href="https://man7.org/linux/man-pages/man8/chpasswd.8.html">chpasswd manual</a> describes it specifically as a batch password-update command and notes that it is intended for larger account-creation environments.</p><!-- /wp:paragraph -->

<!-- wp:heading --><h2 class="wp-block-heading">Basic Syntax and a Safe Lab Example</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p>The input format is simple: one existing username, a colon, and the new password on each line. A lab-only example is <code>printf '%s\n' 'alice:ExampleOnly-ChangeMe' | sudo chpasswd</code>. After the command succeeds, verify the account itself with <a href="https://bitcoinversus.tech/2026/10/02/linux-command-36-getent/"><strong><code>getent</code></strong></a> and inspect password-aging state with <a href="https://bitcoinversus.tech/2026/10/06/linux-command-44-chage/"><strong><code>chage -l</code></strong></a>. Do not treat the example password as a real credential, and do not paste production secrets directly into shell commands that may be retained in history, logs, terminal capture, or automation output. In real administration, the important skill is not merely knowing the syntax; it is controlling where the secret comes from and where it can leak.</p><!-- /wp:paragraph -->

<!-- wp:heading --><h2 class="wp-block-heading">How chpasswd Fits With PAM and /etc/shadow</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p>By default, <code>chpasswd</code> accepts clear-text passwords on standard input and normally relies on <strong>PAM</strong> to perform the password update and encryption work. Local password hashes and aging metadata are associated with <strong><code>/etc/shadow</code></strong>, the same protected account database discussed in <a href="https://bitcoinversus.tech/2026/10/06/linux-command-44-chage/"><strong>Linux Command #44 — chage</strong></a>. The command also has an <code>-e</code> option for input that is already encrypted, but that option changes what <code>chpasswd</code> expects; it does not magically make a plain-text password safe. The Linux-PAM documentation explains that PAM provides the common authentication and password-management framework used by system tools, while the <code>chpasswd</code> manual documents <code>/etc/pam.d/chpasswd</code> as the command’s PAM configuration file.</p><!-- /wp:paragraph -->

<!-- wp:heading --><h2 class="wp-block-heading">Batch Updates, Errors, and Verification</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p><code>chpasswd</code> is valuable because one input stream can describe many password changes, but batch work increases the cost of a mistake. The manual notes an important implementation detail: when PAM performs the updates, a failure for one user can be reported while processing continues for later users; in non-PAM password encryption paths, the utility can stage changes and commit them only after checking the set. Either way, automation should check the command’s exit status and then verify the intended accounts. Pair <code>chpasswd</code> with the account-management commands already covered in this series: <a href="https://bitcoinversus.tech/2026/10/03/linux-command-38-useradd/"><strong><code>useradd</code></strong></a> creates accounts, <a href="https://bitcoinversus.tech/2026/10/03/linux-command-39-usermod/"><strong><code>usermod</code></strong></a> changes account properties, <a href="https://bitcoinversus.tech/2026/10/06/linux-command-43-userdel/"><strong><code>userdel</code></strong></a> removes accounts, and <code>chpasswd</code> updates passwords at batch scale.</p><!-- /wp:paragraph -->
