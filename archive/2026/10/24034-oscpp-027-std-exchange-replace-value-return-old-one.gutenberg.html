std::exchange replaces an object’s value and returns its previous value in one expression. It is especially useful when implementing move operations, transferring handles, resetting state, or writing code where “take the old value, leave a known replacement behind” is the exact intent.

What std::exchange Does

std::exchange is declared in <utility>. Its conceptual form is std::exchange(obj, new_value). The function moves the old value out of obj, assigns new_value into obj, and returns the old value.

The current cppreference entry for std::exchange shows the essential behavior as three steps: create old_value from std::move(obj), assign the forwarded replacement into obj, then return old_value.

Simple example: int old = std::exchange(value, 0);. If value was 42, then after the expression old is 42 and value is 0.

std::exchange Is Not std::move

std::move does not move anything by itself. It converts an expression into an xvalue so that move-aware overloads can be selected. The current cppreference std::move reference describes it as a cast that indicates an object may be moved from.

std::exchange performs an actual two-part state transition: it obtains the old value and then assigns a replacement value into the source object. That makes it useful when you need the moved-from object to immediately contain a specific known state such as nullptr, 0, false, or another sentinel.

std::exchange Is Not std::swap

std::swap(a, b) exchanges the values of two existing objects. After the call, a contains the old value of b and b contains the old value of a.

std::exchange(a, replacement) is asymmetric. It replaces a with replacement and returns the previous value of a. The replacement expression does not receive the old value.

This is why std::exchange is often clearer for “take and reset” operations, while swap is better when two complete object states should trade places.

A Move Constructor Example

Suppose a class owns a raw handle stored in handle_, and the empty state is represented by nullptr. A move constructor can write the transfer directly as Widget(Widget&& other) noexcept : handle_(std::exchange(other.handle_, nullptr)) {}.

Read that expression literally: take the old pointer out of other.handle_, put nullptr into other.handle_, and use the returned old pointer to initialize the new object’s handle_.

The source object remains valid for destruction because it no longer claims ownership of the transferred handle. This is one of the most recognizable uses of std::exchange in resource-owning move constructors.

Why the Moved-From State Matters

For standard-library types, moved-from objects are generally left in a valid but unspecified state unless otherwise documented. Your own resource-owning class must also remain safe to destroy and assign after a move.

Using std::exchange can make that state explicit. A pointer becomes nullptr. A file descriptor can become an invalid sentinel such as -1. A size or count can become 0. The class invariant becomes easier to read because the transfer and reset happen together.

Be Careful in Move Assignment

A move constructor starts with a new object that does not yet own an old resource. Move assignment is different: the destination object may already own something that must be released first.

For example, writing handle_ = std::exchange(other.handle_, nullptr); can leak the resource previously stored in handle_ if assigning the new handle simply overwrites the old one. The cppreference notes for std::exchange explicitly warn about this kind of opaque-resource-handle case.

A correct move-assignment operator must first preserve or release the destination’s existing resource according to the class’s ownership rules. Depending on the design, that may mean cleanup before assignment, a temporary owner, a custom swap, copy-and-swap, or Rule-of-Zero member types that already manage the resource safely.

Different Replacement Types Are Allowed

The template has two types, conceptually T for the object and U for the replacement value. U defaults to T, but it may be a different type as long as the assignment is valid.

This flexibility is intentional. The original WG21 proposal, N3668 — exchange() utility function, revision 3, explains that the second type allows converting assignment and avoids unnecessary temporary objects.

Version History

  • C++14: std::exchange entered the standard library.
  • C++20: it became constexpr.
  • C++23: its exception specification became conditionally noexcept based on whether moving the old value and assigning the replacement can throw.
  • Feature-test macro: __cpp_lib_exchange_function has value 201304L.

The WG21 document list records N3668 as adopted in 2013 for the library work that became part of C++14. The modern standard-library reference also documents the later constexpr and conditional-noexcept changes.

Readable State Transitions

std::exchange is useful outside move constructors whenever a program needs to consume the old state while setting the next state. Examples include replacing a callback pointer, resetting a “first item” flag, taking a numeric counter before clearing it, or updating state-machine variables while preserving the prior state for one expression.

Do not use it merely because it is compact. A normal assignment is clearer when the old value is irrelevant. std::exchange earns its place when both parts of the operation matter: you need the old value and you need the source replaced immediately.

Troubleshooting and Review Checklist

  1. Ask whether the code actually needs the old value.
  2. Confirm the replacement value represents a valid state for the source object.
  3. If the object owns a resource, determine who owns the old resource after the exchange.
  4. In move assignment, confirm the destination’s current resource is released safely before overwrite.
  5. Check whether Rule of Zero can eliminate the custom move code entirely.
  6. Check whether swap communicates the intent better when two full states are trading places.
  7. Check exception behavior if the operation participates in a noexcept move path.
  8. Compile with the intended language standard because availability and exception specifications depend on the C++ version.

Answers

  1. The old value of obj.

  3. std::move changes value category; std::exchange moves out the old value, assigns a replacement, and returns the old value.

Key Takeaway

std::exchange means “give me the old value and leave this replacement behind.” It is compact, expressive, and particularly effective for move constructors and explicit state transitions—but only when ownership and cleanup rules remain correct.
